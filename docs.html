## 01 — Frontend / UI Design

### Concept

The original portfolio was a single index.html file styled to look like a rendered Markdown document in a dark code editor — literal # and ## prefixes visible in the headings, GitHub Dark palette, entirely monospaced. Authentic, but flat.

The redesign kept the concept but pushed it toward technical editorial: the contrast between a pixel display font and a monospace body creates tension that feels designed, not generated.

### Typography — three fonts, one system

Three fonts are loaded, each with a distinct role:

Before — single font
  • Roboto Mono everywhere
  • No visual hierarchy
  • All text competes equally
After — three-font system
  • Press Start 2P — h1 name + nav logo. Pixel bitmap aesthetic, unforgettable at any size.
  • Barlow Condensed — hero description. Wide, thin, editorial. Creates contrast with the pixel name.
  • Roboto Mono — everything else. Preserves the terminal/code identity.

### Glitch animation

The name glitch uses three layered pseudo-elements with clip-path: inset() animated at steps(1) — instant frame cuts, no easing, exactly like a corrupted analog signal. The animation is idle 94% of the time and fires a burst of 5 frames over 6% of a 6-second cycle.

src/css/animations.css — glitch keyframes 
@keyframes glitch-clip-1 {
  /* idle 94% of the time */
  0%,  94%  { clip-path: inset(0 0 100% 0); transform: translate(0); }
  /* 5 rapid frames — analog signal corruption */
  95%        { clip-path: inset(8% 0 72% 0);  transform: translate(-4px, 1px); }
  96%        { clip-path: inset(52% 0 28% 0); transform: translate(4px, -1px); }
  97%        { clip-path: inset(22% 0 58% 0); transform: translate(-3px, 2px); }
  98%        { clip-path: inset(66% 0 12% 0); transform: translate(3px, -2px); }
  100%       { clip-path: inset(0 0 100% 0);  transform: translate(0); }
}

/* Three layers stacked on the same element:
   h1::before  — offset shadow (+3px,+3px), always visible — depth
   h1::after   — cyan tint, animated with glitch-clip-1
   wrap::after — red tint, animated with glitch-clip-2 (offset timing) */

### Isometric cube SVG logo

The logo is a hand-crafted SVG with three <polygon> faces at different gray values to simulate a light source from above-right. The key insight: draw only the visible edges as individual <line> elements — no shared borders that would create unwanted dividing lines across faces.

nav SVG — isometric cube 
<!-- three faces at different luminance -->
<polygon points="16,3 29,10 16,17 3,10"  fill="#c9d1d9"/> <!-- top: bright -->
<polygon points="3,10 16,17 16,29 3,22"   fill="#4a5058"/> <!-- left: dark -->
<polygon points="29,10 29,22 16,29 16,17" fill="#6e7681"/> <!-- right: mid -->

<!-- outer edges ONLY — no shared borders between faces -->
<line x1="16" y1="3"  x2="3"  y2="10" stroke="#0d1117" stroke-width="1.2"/>
<line x1="16" y1="17" x2="16" y2="29" stroke="#0d1117" stroke-width="1.2"/>
<!-- ... 5 more outer edges -->

### Entrance animations

All sections use a single fadeSlideUp keyframe with a spring easing curve (cubic-bezier(0.16, 1, 0.3, 1)) and staggered animation-delay — the page builds itself from top to bottom over ~850ms. No JavaScript involved.

src/css/animations.css — staggered entrance 
.block {
  opacity: 0;
  animation: fadeSlideUp 0.6s cubic-bezier(0.16, 1, 0.3, 1) forwards;
}

.block:nth-of-type(1) { animation-delay: 0.30s; }
.block:nth-of-type(2) { animation-delay: 0.50s; }
.block:nth-of-type(3) { animation-delay: 0.65s; }

## 02 — File Architecture

### Before: 996 lines in one file

The portfolio started as a single index.html with all CSS inline in a <style> block and JS in a <script> tag at the bottom. Functional, but impossible to navigate as the file grew past 700, then 900 lines.

### After: separation by responsibility

Each CSS file has one clear job. When you need to change an animation, you open animations.css. When you need to tweak the nav, you open nav.css. No grep required.

portfolio-markdown/ ├── index.html ← structure only, no inline styles ├── docs.html ← this page ├── src/ │ ├── css/ │ │ ├── tokens.css ← :root CSS variables │ │ ├── base.css ← reset, body, main, scanline overlay │ │ ├── animations.css ← @keyframes + entrance animations │ │ ├── nav.css ← sticky nav + cube logo │ │ ├── hero.css ← hero grid, h1, glitch effect │ │ ├── sections.css ← h2, h3, work entries, badges, education │ │ ├── footer.css ← footer, download CV button │ │ ├── print.css ← @media print (loaded with media="print") │ │ ├── responsive.css ← @media (max-width: 720px) │ │ └── docs.css ← docs-specific: code blocks, metrics, timeline │ └── js/ │ └── cv-download.js ← share/download logic (mobile/desktop) ├── public/ │ ├── cv.pdf ← copied as-is to dist/ by Vite │ ├── og-image.svg ← Open Graph preview image │ ├── sitemap.xml ← for search engine crawlers │ └── robots.txt ← crawler instructions ├── CNAME ← matiasdev.info (fixes domain on every deploy) ├── .gitignore ├── package.json ├── vite.config.js └── .github/workflows/ └── deploy.yml

### Why Vite

Vite handles the build pipeline with near-zero configuration. For this project it does three things: hot-reload in development, bundle + minify all CSS into a single hashed file in production, and copy public/ verbatim to dist/. The multi-page config tells it to treat both index.html and docs.html as entry points.

vite.config.js 
import { defineConfig } from 'vite'
import { resolve } from 'path'

export default defineConfig({
  base: '/',         // works with custom domain
  build: {
    rollupOptions: {
      input: {
        main: resolve(__dirname, 'index.html'),
        docs: resolve(__dirname, 'docs.html'),
      },
    },
  },
})

## 03 — DevOps / CI-CD

### The problem with manual deploys

GitHub Pages supports deploying directly from a branch. The issue: every push overwrites the CNAME file that stores the custom domain binding — meaning the domain would silently detach after each deploy and had to be reconfigured manually in Settings.

### The solution: automated pipeline

A GitHub Actions workflow now runs on every push to main. It builds with Vite, then uses peaceiris/actions-gh-pages to push dist/ to the gh-pages branch — with the cname parameter that writes the CNAME file automatically on every deploy.

git push origin main

Developer pushes changes. GitHub Actions trigger fires automatically.

actions/checkout@v4

Workflow checks out the source code from main.

npm ci

Installs exact versions from package-lock.json. Faster and more reproducible than npm install.

npm run build → dist/

Vite bundles all CSS into one hashed file, minifies JS, copies public/ verbatim. Completes in ~50ms.

peaceiris/actions-gh-pages@v4

Force-pushes dist/ to the gh-pages branch. Writes CNAME: matiasdev.info automatically. Domain never detaches.

matiasdev.info serves the new build

GitHub Pages detects the gh-pages update and propagates globally. Total time: ~30 seconds from push to live.

.github/workflows/deploy.yml 
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: 'npm' }
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
          cname: matiasdev.info  # ← solves the domain detach problem

### Source vs build separation

The main branch contains only source files — HTML, CSS, JS, config. The gh-pages branch contains only the build output — minified, hashed, production-ready. The two never mix. dist/ is in .gitignore and never committed manually.

## 04 — SEO

### Goal: name presence, not keyword ranking

For a personal portfolio, competing for generic terms like "software engineer barcelona" is not realistic. The actual SEO goal is narrower and achievable: when someone googles "Matías Agnolin", this site should appear immediately and look professional when shared as a link.

### Open Graph — controlling link previews

Open Graph meta tags control what LinkedIn, WhatsApp, Slack and iMessage show when you paste the URL. Without them, crawlers guess — usually badly.

index.html — Open Graph tags 
<!-- tells crawlers the canonical URL -->
<link rel="canonical" href="https://matiasdev.info" />

<!-- controls LinkedIn / WhatsApp / Slack preview -->
<meta property="og:title"       content="Matías Agnolin — Software Engineer" />
<meta property="og:description" content="10 years building data-intensive systems..." />
<meta property="og:image"       content="https://matiasdev.info/og-image.svg" />

<!-- controls Twitter/X preview -->
<meta name="twitter:card"  content="summary_large_image" />
<meta name="twitter:image" content="https://matiasdev.info/og-image.svg" />

### Structured data — Person schema

A application/ld+json script block tells Google explicitly who this page is about. This is the mechanism behind Google's Knowledge Panel — the summary box that appears on the right side of search results when you search for a person's name.

index.html — JSON-LD Person schema 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Matías Agnolin",
  "jobTitle": "Software Engineer",
  "url": "https://matiasdev.info",
  "sameAs": [
    "https://github.com/matiasagnolin",
    "https://linkedin.com/in/matiasagnolin"
  ]
}
</script>

### sitemap.xml + robots.txt

sitemap.xml tells crawlers which URLs exist and their relative priority. robots.txt tells crawlers they're allowed to index everything and where to find the sitemap. Both live in public/ so Vite copies them unchanged to dist/.

### Google Search Console

Once the site is live, verifying with Google Search Console lets you: submit the sitemap directly, request immediate indexing, and see if Google encounters any crawl errors. Verification is done by adding a single <meta name="google-site-verification" ...> tag to the <head>.

## 05 — Performance

### Build output

Vite bundles all 9 CSS files into a single minified, content-hashed asset. The entire runtime payload is under 4 KB gzipped.

8.58 kB CSS bundle 2.46 kB gzipped
1.40 kB JS bundle 0.72 kB gzipped
0 Runtime deps zero JS frameworks
49 ms Build time local, Vite 6

### Zero runtime JavaScript dependencies

Every visual effect on the page — the glitch animation, entrance animations, hover states, scanline texture, sticky nav blur — is pure CSS. No animation library, no scroll observer, no React, no Vue. The only JavaScript that ships is the CV download/share button (1.4 kB), which uses the native Web Share API on mobile and a programmatic <a download> click on desktop.

### Google Fonts loading strategy

Three techniques prevent Flash of Unstyled Text (FOUT) and minimize render-blocking:

index.html — font loading 
<!-- 1. preconnect: opens TCP connection early, before CSS is parsed -->
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />

<!-- 2. display=swap: renders fallback font immediately,
        swaps to web font when loaded — no invisible text -->
<link href="...&display=swap" rel="stylesheet" />

<!-- 3. only the weights actually used are requested:
        Roboto Mono: 100,200,300,400,600
        Barlow Condensed: 200,300,700,800
        Press Start 2P: 400 only (one weight, one file) -->

### Scanlines without images

The subtle scanline texture overlay on the background is generated entirely in CSS using repeating-linear-gradient — no PNG, no SVG, no extra HTTP request. At 3% opacity it adds depth without affecting readability.

src/css/base.css — scanline texture 
body::before {
  content: "";
  position: fixed;
  inset: 0;
  background-image: repeating-linear-gradient(
    0deg,
    transparent,          transparent          2px,
    rgba(0,0,0,0.03) 2px, rgba(0,0,0,0.03) 4px
  );
  pointer-events: none;  /* never blocks clicks */
  z-index: 999;          /* always on top */
}
